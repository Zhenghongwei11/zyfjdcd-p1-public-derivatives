# 规范化政策（v0.1）

## 1. 总原则

1. 规范化永远不覆盖原文层。
2. 规范化目标是“可计算、可复核”，不是“重写原书”。
3. 无法稳定规范化时，宁可保留 `raw` 并标记待定，也不做武断合并。

## 2. 方名规范化

- `headword_raw` 保留 OCR 观测值
- `headword_norm` 用于后续聚类和去重
- 仅同名不自动合并为同方
- 同方异名归并至少需要以下证据之一：
  - 显式“异名/见该条”引导
  - 一致的出处与高度一致组成
  - 经人工裁决确认

## 3. 药名规范化

建议采用“双层表示”：

- `herb_raw`：原文药名片段
- `herb_canonical`：规范化药名

当前优先级：

1. 国家药典或通行中药学标准名
2. 主流中药学教材/标准词表
3. 若无稳定映射，则保持原文并标 `canonical_pending`

## 4. 炮制与修饰信息

如下信息不应直接丢失：

- 炮制法
- 部位
- 产地/来源修饰
- 制剂相关描述

处理规则：

- 基础药名进入 `herb_canonical`
- 炮制/修饰另入 `processing_items_norm`

## 5. 剂量规范化

- 保留 `dose_raw`
- 可解析时拆成 `dose_value` 与 `dose_unit`
- 不强行把古代量纲换算成现代克数

## 6. 字段文本规范化

- 去除纯格式噪声不等于改写语义
- `# 【主治】` 这类误标题可在结构化层统一映射为 `indication`
- 段内异常空格、OCR 断裂可在 `normalized_text` 层轻量修复，但 `raw_text` 必须保留

## 7. 禁止的自动化合并

- 只因同名就判定为同方
- 只因有同一核心药对就判定为同方
- 把炮制差异全部吞并到基础药名
- 把现代成药条目与古籍方自动合并

## 8. 待后续补齐

- 正式规范词表来源版本
- 特殊古今异体药名映射表
- 数词、量纲、括号炮制语的解析细则

# 标注指南（v0.1）

## 1. 总原则

1. 原文层与规范化层分开标。
2. 不要把“你认为应该是什么”直接改写成标注真值。
3. 遇到 OCR 疑难点，优先保留原文证据并打不确定标记。

## 2. 通用规则

### 2.1 标注单位

- 文档类型：连续行块
- 条目切分：单条方剂相关记录
- 字段抽取：条目内字段跨度
- 药名规范化：组成字段中的药物项
- 异名归并：方名对或方名簇

### 2.2 原文保留

- 原始字符、标点、错行和 `# 【字段】` 之类噪声在 source/raw 层保留
- 任何人工判断都不能覆盖 `raw_text`

### 2.3 不确定性

以下情况必须标 `uncertain` 或进入裁决：

- 编号不完整但疑似存在
- 同一片段可能切成一条或两条
- 字段标题被截断
- 药名与炮制信息黏连无法稳定拆分

## 3. 任务级规则

### 3.1 文档类型分类

- 优先看功能而不是形式
- 出现 `<html><body><table>` 的片段，默认先判 `TABLE_HTML`
- 若同一片段同时含目录和条目，先判 `MIXED_UNKNOWN`

### 3.2 条目切分

默认边界规则：

- 起点优先为 5 位编号开头
- 若无编号但明确是异名引导条，也可单独成条
- 终点为下一条起点前一字符

困难情况：

- `【主治】` 或 `【备考】` 末尾直接粘到下一编号，仍要人工切开
- 单条内部缺换行，不视为自动分条依据

### 3.3 字段抽取

- 只标原文中实际出现的字段
- 字段标题错写成 `# 【用法】` 仍按 `usage` 处理
- 引导条默认不标正文字段
- 一个字段跨多行时按连续跨度整体标记

### 3.4 药名规范化

- 先从 `composition_raw` 中分出药物项，再做规范化
- 炮制、部位、剂型、修饰语尽量拆为附属属性，不直接吞掉
- 识别不清的项可保留 `raw_component` 并标 `norm_pending`

### 3.5 异名归并

- 明确“为某方异名，见该条”者，可直接记为强别名证据
- 仅同名不等于同方
- 同名异方必须优先看出处、组成或明确引导语

## 4. 裁决规则

1. 先按指南独立双标。
2. 分歧样本进入裁决表。
3. 裁决优先级：
   1. 条目边界
   2. 文档类型与任务资格
   3. 字段跨度
   4. 规范化与归并

## 5. 当前禁止做法

- 直接依据常识补出缺失药名
- 因为条目太脏就静默丢弃
- 把目录、前言、版权页当作负样本却不记录来源
- 把同名直接当作同方

## 6. GUI 标注（Label Studio）

本项目当前推荐使用 Label Studio 做首轮 GUI 标注（分类 + span）。

- 配置文件：`annotation/label_studio/label_config.xml`
- 首轮样本任务：`annotation/label_studio/tasks/sample_pack_v1.json`
- 说明：`annotation/label_studio/README.md`
